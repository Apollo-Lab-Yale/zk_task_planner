\subsection{Hybrid YOLO Implementation}
\label{subsec:hybrid_yolo}

Our perception system employs a novel hybrid approach that combines YOLOWorld for object detection with FastSAM for instance segmentation.

\subsubsection{YOLOWorld and FastSAM Integration}
\label{subsubsec:yolo_fastsam_integration}

 YOLOWorld first identifies object instances and their bounding boxes in the scene, providing class-agnostic detection with customizable vocabulary. For each detected object above the confidence threshold $\tau_c$, we extract the corresponding bounding box region and apply FastSAM segmentation to obtain object masks.

 For each bounding box region, FastSAM generates multiple candidate masks, and we select the mask with the largest area as the most likely representation of the target object. The extracted masks are then projected back to full image coordinates and combined with the original detection metadata to create object representations containing both classification and spatial information.


\subsection{Region of Interest Detection}
\label{subsec:roi_detection}

The region of interest (ROI) detection system identifies interaction points within detected object masks using a multi-modal approach that combines contour-based geometric analysis with depth-based 3D feature detection.

\subsubsection{Contour-Based Feature Extraction}
\label{subsubsec:contour_features}

Harris corner detection is applied to object contours to identify sharp geometric transitions that often correspond to graspable edges, handles, or structural features. Points with high corner response values are retained with confidence scores proportional to their response strength. Complementing corner detection, curvature analysis identifies high-curvature points along object contours that indicate significant shape changes corresponding to functional features such as handles, knobs, or graspable protrusions. Points exceeding a curvature threshold are classified as interaction candidates with confidence scores based on local curvature magnitude.

\subsubsection{Depth-Based Analysis}
\label{subsubsec:depth_analysis}

The depth analysis stage identifies 3D structural features that may not be apparent in 2D image analysis alone.

\textbf{Depth Discontinuities:} Sobel gradient computation on the depth image detects abrupt depth changes corresponding to object boundaries, handles, or protruding features. Each detected edge point is scored by its gradient magnitude normalized against the maximum gradient within the object mask, yielding $s_i \in [0, 1]$.

\textbf{Protrusions and Indentations:} Multi-scale convolution at three kernel sizes computes local mean depth within the object mask. Regions where depth is significantly less than the local mean (closer to the camera than their surroundings) are identified as protrusions, while regions where depth significantly exceeds the local mean (further from the camera) are identified as indentations. Each detected feature point is scored by its depth prominence, the magnitude of deviation from the local mean, scaled and clamped to $[0, 1]$. A second detection pass using Gaussian kernels at multiple scales performs connected component analysis on the thresholded deviation maps, scoring each region by a combination of three factors: the mean depth prominence within the region, the shape compactness measured by the isoperimetric ratio $4\pi A / P^2$ (where $A$ is the region area and $P$ its perimeter), and a consistency term inversely proportional to the standard deviation of depth values within the region.

\subsubsection{Point Filtering and Re-Scoring}
\label{subsubsec:multimodal_fusion}

All detected points from all methods are pooled and filtered through greedy non-maximum suppression (NMS), which iterates through points in descending score order and suppresses any point within a minimum pixel distance of an already-selected higher-scoring point. After NMS, each surviving point's score is refined as a weighted combination:

\begin{align}
    s_i = w_b \cdot s_{base}^i + w_t \cdot s_{tex}^i + w_d \cdot s_{depth}^i + w_e \cdot s_{edge}^i
\end{align}

where $s_{base}^i$ is the original detection score from the method that produced the point, $s_{tex}^i$ is a texture penalty computed from the Laplacian response that penalizes points on highly textured regions where depth estimates are less reliable, $s_{depth}^i$ is a depth reliability term inversely proportional to local depth gradient magnitude, and $s_{edge}^i$ is a boundary distance term favoring points near but not on the object contour. The re-scored points are ranked and the top-$k$ candidates are selected for primitive parameter generation.

\subsubsection{3D Point Generation}
\label{subsubsec:3d_point_generation}

Selected 2D interaction points are converted to 3D coordinates using the pinhole camera model. Given pixel coordinates $(u, v)$ and the corresponding depth value $z$, the 3D position is computed via backprojection using the camera intrinsic matrix $\mathbf{K}$ with focal lengths $(f_x, f_y)$ and principal point $(c_x, c_y)$. This 3D representation enables spatial reasoning about interaction points during skill generation and provides the coordinates used for robot motion planning.

\subsubsection{Surface Mask Generation and Filtering}
\label{subsubsec:surface_filtering}

Candidate surface masks are generated by applying FastSAM in prompt-free segmentation mode to the scene image. The resulting masks are filtered by area to retain only functionally relevant surfaces, removing both small noise artifacts and overly large background regions. Each validated surface receives a unique alphabetical identifier used to reference the surface in primitive parameter specifications.

For each validated surface mask, a 3D point cloud is extracted using the same backprojection described in Section~\ref{subsubsec:3d_point_generation}, with depth values filtered to the valid range and downsampled for efficiency. Surface normal estimation is then performed using RANSAC plane fitting on this point cloud. The algorithm repeatedly samples three random points, computes a candidate plane normal from their cross product, and counts how many points in the cloud lie within a distance threshold $\delta_{max}$ of the candidate plane. After $T$ iterations, the plane hypothesis with the most inliers is selected as the best-fit model, and its normal vector $\hat{\mathbf{n}}_s$ is taken as the surface normal. The fitting confidence is the inlier ratio $c_{fit} = N_{inlier}^* / N_{total}$, which directly reflects how well the surface conforms to a planar model.

The surface normal $\hat{\mathbf{n}}_s$ and centroid $\mathbf{c}_s$ provide the spatial characterization required for primitive parameter generation. The normal determines approach direction for push and pull primitives---perpendicular approach aligns the end-effector along $\hat{\mathbf{n}}_s$, while parallel approach uses a direction orthogonal to $\hat{\mathbf{n}}_s$ within the surface plane. The centroid serves as the default contact point when no specific interaction point is specified.



\subsection{Parameter Generation and Primitive Execution}
\label{subsec:parameter_generation_execution}

The perception system outputs are compiled into visual parameter representations that enable the LLM to generate executable primitive sequences. This section describes the parameter compilation process and primitive execution pipeline.

\subsubsection{Visual Parameter Compilation}
\label{subsubsec:visual_parameter_compilation}

The system generates two specialized visualizations for LLM input: a surface-focused image showing environmental surfaces with alphabetical labels (\texttt{aaa}, \texttt{aab}, \texttt{aac}) and normal vector arrows, and an interaction point image displaying colored circles at manipulation locations with corresponding labels. The target object is outlined with a yellow boundary to constrain parameter selection, and edge labels (\texttt{top}, \texttt{bottom}, \texttt{left}, \texttt{right}) provide reference points for hinge location specification.

\subsubsection{LLM Primitive Parameter Mapping}
\label{subsubsec:llm_parameter_mapping}

The LLM receives structured prompts that explicitly map visual elements to primitive parameters. Surface labels from the first image correspond to push/pull targets, while interaction point circles from the second image provide gripper positioning coordinates.
